# Snack portal route failure recovery

A failed `portal.attach(container)` can occur before the child outlet takes portal
ownership. Restoring the child as host in that state caused the next
`portal.detach()` to leave the container attached, and development-mode retry
failed. The untouched tagged caller permits that retry.

The repair remembers the development validation boundary before public dispatch.
It restores the container for that boundary and retains the child-owned state for
failures after ownership has transferred. This preserves the tagged production
behavior too. The callback signature, constructors, imports, other 31 class
members and all 1,141 other product/resource members remain unchanged. No HTML,
CSS or SCSS change is required.

The original 105-case proof and its program remain intact. The extended oracle
uses the same untouched tagged source and authenticated complete minimum peer
archives. Three strict type models have no diagnostics and the repaired callers
use no deprecated or planned-removal public signatures. Ten real Core/CDK runtime
combinations exercise 115 cases and reject 40 applicable behavior faults. The
immediate prior repair is an actual source-bound negative control for the five
development-mode runs; its production behavior is preserved. The existing unused
peer `attachedRef` empty-default distinction is still recorded separately.

The runtime fixture extracts actual caller methods and uses explicit receiver,
renderer and DOM protocols with genuine public outlets. It does not execute a
full snack-bar instance or qualify browser, packed-consumer, Node/RxJS/compiler
floors or G01–G13. The Cyph check was read-only; no direct custom portal/container
uses matched, and its normal snack service/module routes need no change. Cyph was
not built.

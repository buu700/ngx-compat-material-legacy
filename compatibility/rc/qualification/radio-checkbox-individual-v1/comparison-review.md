# Radio pointer and checkbox forced-colors comparison

The specific radio host pointer and checkbox disabled opacity differences do not establish a legacy parity failure: in this focused browser comparison, the current packed legacy controls matched the original Material 16.2.14 controls, while the 22.1.7 modern controls differed. This supersedes the earlier source-only suggestion that checkbox opacity was an unqualified legacy gap. It does not establish universal accessibility or waive other gates.

The isolated fixture renders actual Angular components and public MatTooltip in three separate bundles: reference `@angular/material` and CDK 16.2.14 on Angular 16.2.12; owned radio/checkbox from the retained packed tar SHA256 `2cf96975b6f6adaa83a8bf42f99a756f34bbdd7166ea899120f5605c66f8bffb` on Angular/CDK/Material 22.1.7; and current 22.1.7 peer. Chromium reported `Chrome/156.0.8078.79`; forced colors were emulated with CDP and `matchMedia` confirmed active. Component styles were loaded; no application theme or custom consumer CSS was added. The fixture uses noop animations, separate Angular instances, and actual CDP pointer movement and clicks.

For disabled radio, tagged16 and packed legacy both computed host `pointer-events: auto`; `elementFromPoint` hit the radio outer circle, pointerover and click reached the radio host, the public tooltip opened, and the input stayed unchecked and unfocused. The modern peer computed `pointer-events: none`; the hit was the ancestor, the host did not receive the event, and its disabled tooltip did not open. Enabled positive controls selected and focused in all three, and their public tooltips opened. This tests the separate default disabled host rule in `0af3b617505d5f39f2492ba4b7e3e7fd4b74f990`; the new interactive-disabled opt-in API remains outside the Material 16 legacy contract. These findings concern the tested host hit point, not every pointer location, browser or application tooltip wrapper.

For forced colors, enabled unchecked and disabled unchecked, checked and indeterminate public checkbox instances were observed. Tagged16 and owned legacy matched all captured computed host, frame, checkmark, mixed-mark and label properties in these four cases: enabled host opacity 1; each disabled host opacity 0.5; observed forced-color frame and mark colors black. The modern peer used disabled host opacity 1 and GrayText `rgb(96, 0, 0)` on the disabled frame/mark in this emulated color scheme. This tests the mechanism in `ff9059d8d14b82a465481e51f01582caf6d83b6c`; it establishes reference parity and a peer difference, not a general contrast measurement or a demonstrated accessibility failure. Inactive controls have specific contrast-exemption context, but that does not establish usability in every forced-color palette. No modern-style backport is justified by these observations alone.

# Five upstream radio and checkbox a11y changes: independent source triage

Reviewed the complete named commits in the local upstream object database against the owned 16.2.14 legacy implementation and current tree `5ddd6f98b9af8c4b4f7bee619eb291c2a9950b1c`, installed minimum Angular Material 22.1.7, and existing tests. This is source triage, not runtime or screen-reader qualification. The separate `fc36` radio fix is outside scope. Mechanical inherited classifications are not proof of individual applicability.

* `0af3b617505d5f39f2492ba4b7e3e7fd4b74f990`: The radio input/group/default `disabledInteractive` option, new aria-disabled/focus-without-selection behavior and related MDC styles are a new opt-in API, absent from the 16.2.14 legacy contract and current owned class, not an automatically required legacy feature. The commit also independently moves default disabled `pointer-events: none` from the MDC control to the whole MDC host. Owned radio instead preserves the tagged legacy label/input structure: native input disabled, ripple pointer-events none, disabled cursor default, and no host-wide pointer-events rule. The host event/tooltip hit-testing behavior is observably different in source; whether this separate MDC host correction addresses a legacy defect has not been demonstrated. Next test: separately click/hit-test input, label, container and host on a disabled owned control, observe native selection, focus, bubbling and ancestor tooltip behavior, and compare to untouched 16 reference. Do not add the modern input or change legacy hit testing solely to mirror peer behavior.
* `eba6ee844b8e8e6044e1675b5e41ff13224ead75`: Applicable type/contract gap. The upstream patch widens all three radio `ariaLabel`, `ariaLabelledby`, `ariaDescribedby` inputs from `string` to `string | null` and tests removal after null. Current owned declarations and retained packed declarations are still `string` at radio-base lines 351–357, so strict nullable consumers cannot type-check the reset. The legacy HTML binds each directly through `[attr.aria-*]`, suggesting Angular can remove it at runtime, but that was not run here. Existing tests only check setting/updating non-null values. Next test: packed strict-template/AOT fixture bound to `string | null`, plus separate rendered set→null assertions for all three and restoration; this distinguishes type and runtime behavior. A bounded nullable type fix must preserve actual template/attribute behavior and be independently qualified.
* `a62e65971a379715b8bae2e437e67b62c113a263`: The original screen-reader issue is an MDC `.mat-mdc-radio-touch-target` with its own click listener; the patch removes that listener and makes the input part of a wrapping label. The owned legacy `radio.html` already wraps the input in its label, contains no touch-target element and does not bind `_onTouchTargetClick`; the remaining method is exercised directly by a legacy test but is not attached to the relevant template. Therefore this specific original node/listener exposure is not present, rather than inherited by import. This source finding is not a blanket screen-reader accessibility claim. Next focused check: assert the rendered legacy DOM has no separate clickable touch-target, that label activation reaches the native input once and disabled input does not select; actual assistive-technology behavior remains untested.
* `8417601015e7c3a96a8a6801213e764058ee8aba`: The checkbox `disabledInteractive` input/default and aria-disabled-but-focusable handling are a post-16 opt-in feature absent from the promised legacy API. Legacy checkbox uses a native disabled input and owned 16-era markup; no modern API mirror follows from the peer change. Repro if the boundary needs a positive control: confirm a disabled legacy checkbox remains natively disabled, cannot change from pointer/keyboard and emits no change, alongside an enabled control; do not claim the peer's new interactive-disabled behavior is inherited.
* `ff9059d8d14b82a465481e51f01582caf6d83b6c`: Applicable visual/accessibility risk, not safely excluded merely because the original selectors are MDC. Upstream removes half-opacity disabled presentation and sets GrayText for disabled border/check/mixed marks and label in high contrast. Owned `legacy-checkbox/checkbox.scss` also applies opacity 0.5 to `.mat-checkbox-disabled` under `high-contrast(active, off)` (lines 426–431), while its frame, SVG checkmark and mixed mark use different legacy DOM and styles. The specific low-visibility mechanism therefore exists in source; visible impairment and a safe fix are not yet proven. Next run forced-colors browser tests/screenshots for enabled/disabled × unchecked/checked/indeterminate, inspect computed opacity and system colors, compare untouched tagged reference and current peer, and review affected legacy styles without selector changes or hiding reference failures. No claim that a particular GrayText patch is already proven appropriate.

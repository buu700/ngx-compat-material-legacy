# Proposed narrowly owned operation and controls

This is a design, not an implementation or a valid production review packet. `candidate-review-records.json` deliberately says `proposal-not-reviewed`; it keeps the schema's per-key fields and independently linked historical evidence, but sets `candidate_source_sha256` to null for the 23 missing sources. The current validator rejects those records. Its `source_successor` object is illustrative and has no authority until the shared-contract owner reviews and implements a finite operation. `candidate-source-data.json` carries exact row identities, preimage Git blobs, physical current observations, 21 family/module/barrel pairs, two package barrels, peer declaration inputs and the complete old evidence comparison. The graph hashes are inputs to a future reviewed qualification, not independent proof by themselves.

## Integration contract

1. Before constructing a successor, authenticate the frozen seed `3e059e3d…`, all 25 exact BidiModule keys and the current roster's original 25 row identities. Verify exactly one original review case per key in `public-bidi-module-boundary.json`, the document hash `63b2265f…`, and each decision and original independent evidence. Authenticate the original old source at `0c25c562…` through Git object bytes, no replacement objects or lazy fetch, and match each case's `candidate_source_sha256`. Historical evidence must stay recorded at its own exact bytes. In particular the two old producer files now differ; authenticate their old bytes against the review pins with Git/history or an immutable archive, review their complete changes and bind the separate current producer/test qualification. Merely referencing the original review file does not validate its now-changed direct evidence.
2. Verify MAIN package line and exact declared `^22.1.7` core/CDK/Material floor; independently authenticate the CDK 22.1.7 public BidiModule and Dir declarations/export and historical subject capsule at its existing hash. Treat the installed package/version/declaration hash as a physical snapshot, with an authenticated installed-package provenance or SRI-bound capsule for future approval. No assumption that checking `node_modules` version alone authenticates package bytes. Check real public module use: owned core imports and exports BidiModule, pseudo-checkbox imports and exports it alongside its component, with TypeScript binding-aware proof against alias and shadow changes. Avoid private Angular/CDK metadata as a source of claimed public runtime behavior.
3. Require precisely the immutable 23 retired paths and 2 retained paths from the seed, with no additional or duplicate cases. For the 23, physically establish absence (including no dangling symlink or symlink ancestor, traversal or alternate root), and check their original 23 Git blobs and reviewed old roles. For 2, require regular nonlinked physical current files with hashes identical to their old reviewed sources; they continue as stable-public-peer. Do not supply historical bytes as if they were current. Respect the raw reader contract: any supplied reader must equal independently obtained current physical bytes for present files and must not synthesize bytes for absent paths.
4. Verify exact historical-to-current source transition for each family owner and public barrel, uniqueness of all 21 owners and their NgModule import of the owned legacy-core alias. Independently bind core module, core public alias and root public barrel and account for the two nonfamily root stub keys. Verify the 44 exact owner/barrel transformations in the data and check package/family source namespace through a binding-aware scanner; ensure no unrelated new family owner, reintroduced peer binding, or hidden Bidi route is silently excluded. Do not equate removal of the family/root accidental public export with removing core's `MatLegacyCommonModule`. The source graph and current census must be one physical source snapshot, with all hashes and absences rechecked after inspection and reentrancy/reader swaps rejected.
5. Extend the source-evidence owner, not the generic notion of `removed-use`: on the normal production review path, retain existing nonempty-current-source semantics for all cases; only when a selected key matches the exact allowlisted 23 main Bidi retirements and an independently verified finite qualification succeeds may that specific row's physical-source predicate be replaced with the explicit historical-plus-absence-and-graph predicate. Continue checking the schema, nontrivial per-case decision, reviewer, current proof and every evidence hash. Two retained records follow the normal present-source predicate with successor evidence for the changed producers. Fail closed if qualification cannot be established; do not allow arbitrary candidates to specify their own path list, line, hashes or boolean authorization. Historical `readMember` fixture access must never escape into current raw source checks. A bounded per-row qualification result may attach a distinct proof reference but must not substitute current source bytes or erase any existing key.
6. Stage a complete proposed review packet only after independent review; bind the old full review and exact per-case identity plus the authenticated new finite source result and every still-applicable old direct evidence. Preserve all 25 roster keys and statuses until the owning process decides them, preserve all unrelated rows and evidence byte-for-byte, and compare before/after full inventory and new live-use census. Historical runtime results keep their source/artifact identity and original labels. Re-run the production validator on a disposable fixture; no expected reviewed count or G11 result is a semantic audit claim.

The current `authoredUseReviewEvidence` signature only receives `candidate, line, readMember, sha256`, not a trusted physical root, inventory scan or qualification context. A secure finite integration therefore needs a reviewed caller/contract change that gives the owned successor access to an anchored physical root and current graph, or another owner-controlled, non-forgeable qualification path. A candidate-controlled callback, general `missing` flag, synthetic old-source reader or global `removed-use` exemption would be unsafe. The existing additional-use retirement code is a relevant exact source-epoch example, **not** an existing exception for this frozen roster: it deals with preserved removed additional-use obligations and a present source file, whereas these are absent frozen paths.

## Required controls before any production change

- Positive: exact current main graph yields 23 explicit retirements and two physically present retained uses; historic fixture alone reproduces its old 25 historical bindings; mixed old/current claims stay distinct.
- Population: each omitted, duplicated, reordered-with-loss, extra or substituted key and wrong module/symbol fails; unrelated rows and independent evidence are preserved and the broad frozen inventory count/identity is unchanged.
- History: wrong Git base or object, missing history, review/case/seed alteration, wrong old file path/blob, old/current hash swap, replacement refs or unexpected Git environment fail; do not fetch history automatically.
- Physical/source: reintroduce any one old path (including broken symlink), link an ancestor or present proof/source path, replace root, change a present core source, alter raw reader bytes, mutate source between reads, forge missing path or reenter during reads: each fails. Recheck both present and absent paths after graph acquisition.
- Graph: remove Bidi import or export in core or pseudo-checkbox; change metadata by alias/shadow/dynamic composition; substitute modern Material or foreign class for each family owner; delete one family, duplicate an owner, change family module metadata, reintroduce a public ordinary common class in any family/core/root barrel, remove historical core alias, or mutate a current namespace edge; each fails. Detect new unexpected uses rather than assuming the fixed 21 paths exhaust the graph.
- Peer/line: wrong main package major, changed core/CDK/Material floor, wrong CDK version, export identity, declaration bytes or source capsule, old 21-only data, or any late change during read fails; actual 21.x must not be claimed by a main-only negative test.
- Evidence: individually corrupt or remove every original evidence, historical producer/test, current public probe, current Python test, namespace successor, source qualification and receipt, including producer/test afterimage mismatches; each relevant use fails closed. Preserve historical source diagnostic `producer_sha256` and artifact hashes exactly.
- Regression: regular production rows with missing current sources or arbitrary `removed-use` remain insufficient; no unqualified old Bidi case passes; no unrelated inventory/review/evidence is rewritten; a partial qualification never credits the other rows. Verify failure routing through all production callers, including callers that use historical source readers.

Existing qualification records describe 73 source mutants, 36 original/minimum public-namespace cases and 17 runtime mutants for the earlier source frame. They are useful inputs for a future replay and do not replace these integration controls. No test in this list was run for this proposal.

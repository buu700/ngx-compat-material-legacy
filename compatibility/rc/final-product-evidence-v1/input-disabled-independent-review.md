# Independent legacy native-input disabled fix V6 review

Disposition: no blocking behavioral finding in the bounded tests and source review. This approves the standalone V6 repair for consideration, subject to a specific API disposition for the added protected members and requalification of any later composition with the separately owned control-swap patch. No canonical source was changed.

The exact patch SHA-256 is `5b6c4c34229b5b162b19f50649f1921f76e944014c90f0ebffc8581b040b36d3`. It applied cleanly to independent copies of the two current canonical input files. The baseline and candidate are diagnostic synthetic packs, not newly produced coordinator-bound artifacts.

Tagged 16.2.14 `src/material/input/input.ts` binds native `disabled` to its disabled state and readonly only for a readonly non-select. Current peer 22.1.7 exposes public `disabledInteractive` and `ngDoCheck()` with no deprecation/docs-private tags. The patch forces the inherited interactive setting false after parent construction and before parent `ngDoCheck`, supplies native disabled and non-select readonly bindings, suppresses the peer interactive MDC class, and snapshots the current authored `aria-disabled` attribute for the owned host binding. It imports no peer private symbols and makes no consumer HTML/CSS/SCSS change. It intentionally neutralizes the inherited `disabledInteractive` input at check time: this is behaviorally conservative relative to Material 16, but consumers can still see that inherited input in the current Angular declaration. The API owner agrees this should not be advertised as a supported legacy feature. The candidate declaration also adds protected `@docs-private` `_legacyAriaDisabled` and `_legacyReadonlyAttribute`, as required by strict Angular host-template compilation; these need a specific proof-backed API disposition and must not be silently ignored as a blanket docs-private exception.

Independent actual AOT browser test used the owner candidate tar SHA-256 `b06a4e25f73c262f5cd7824de705a5591f1e4026ea4895ce4e2a5b29a34efe31` and baseline tar `fbea62412013d2915c27801117dfda44ff550a0c392d599b4846c46719dd6a8c`, Angular/CDK/Material 22.1.7, Node 24.21.0 and Chrome/149.0.7827.0 via the existing raw helper; no browser-disabling flags were supplied and sandbox state was not queried. In a separate zoneless strict-template standalone app with global peer config `disabledInteractive:true`, plus one explicit `[disabledInteractive]="true"`, initial input, textarea, select, reactive form control and static/dynamic ARIA controls all had native disabled true and no interactive MDC class on candidate. The baseline produced native disabled false on all six; input and textarea acquired readonly and the select was interactive. Candidate enable/readonly and subsequent disable/reactive-control transitions were correct; authored static `aria-disabled="false"` survived, dynamic null→true→false→null was preserved, and external attribute add/remove was reflected. The public inherited property read false after checking. `assert-results.mjs` accepts candidate, rejects the baseline, and rejects four deliberately altered observation objects; those are assertion controls, not mutated library runtimes.

A separate Angular 22.1.7 `renderApplication` SSR test with strict full-AOT app compilation and the same candidate package rendered disabled input, textarea and native select; all serialized the disabled attribute without readonly or interactive MDC class, and the author's `aria-disabled="false"` survived. The library's partial code was handled at runtime with the Angular compiler/JIT fallback, not a fully linked production SSR bundle. The first SSR attempt failed the platform's host validation before rendering; a rerun explicitly allowed only localhost and passed. This does not qualify hydration or arbitrary server/custom renderers.

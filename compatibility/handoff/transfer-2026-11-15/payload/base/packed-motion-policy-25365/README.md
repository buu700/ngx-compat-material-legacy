# Packed legacy motion-policy DI probe

All 20 provider cases and outside-context controls passed against actual public exports from the supplied 25365 packed library, with Angular 22.1.7 `EnvironmentInjector`/`runInInjectionContext` and nix Node 24.21.0. `results.json` contains the per-case state, disabled flag, five resolved modes and media queries. `probe.mjs` has the exact independent assertions; `inventory.json` binds the tarball, copied package, module, source map, and current helper source. The caller-supplied extraction and tested copy were unchanged and matched all 512 regular tar members.

Expected contract was derived before running from the frozen owned helper's documented no-ambient-DI policy and its finite token selection: explicit Noop stays Noop; outside DI there is no ambient policy, so other explicit modes are retained; an enabled ambient policy preserves modes; disabled or reduced ambient policy resolves them to Noop. In DI, the test override takes precedence, then `MATERIAL_ANIMATIONS` disabled, then the owned `LEGACY_ANIMATION_MODE` Noop, then reduced-motion preference; absent MediaMatcher is enabled. The provider matrices test those edges, a disabled/enabled Material token, and child overrides of parent providers for both owned mode and Material config. The reduced-motion MediaMatcher is a controlled protocol that records the query, not a browser media emulation.

The old `ANIMATION_MODULE_TYPE` token alone does not affect the owned helper: old Noop and old Browser each leave the policy enabled in the no-reduced-motion configuration. This is an intentional observable API behavior change, not an equivalence claim for the old token or automatic migration of existing Noop providers. The outside-context direct `getLegacyAnimationsState()` call throws NG0203; the disabled and mode resolver exports deliberately support outside-context use. The existing checkbox manual-construction evidence is separate and was not rerun.

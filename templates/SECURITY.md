# Security policy

Before public publication, the repository owner must configure a private reporting channel (for example GitHub private vulnerability reporting) and document the verified contact here. Do not claim a reporting channel exists until it is enabled. Do not publish exploit details merely to obtain a maintainer response.

Report affected versions, reachable code path, impact, reproduction and proposed fix privately. Distinguish build-tool findings from shipped runtime exposure. Maintain the tested supported peer matrix and inspect relevant upstream Material/CDK fixes; copied legacy logic does not inherit patches automatically.

No independent security audit is claimed. Releases require reviewed fixes, tests and owner authorization. Unsupported versions are identified in the published compatibility matrix.
